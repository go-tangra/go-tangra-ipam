# ipam join bundle

Generated by the gateway (Gateway operations › Modules › ipam › Add).

    docker compose up -d

`private/` holds credentials (the single-use enrolment token, the bundle's
TLS keys); `.env` holds generated passwords and the key-encryption key;
`config.yaml` holds the event-bus password you gave. Keep them on this host
only, and back up `.env` with the `ipam-db` volume: sealed fields cannot be
read without the key. The enrolment token is valid for the lifetime chosen
in the wizard; after the first start the module renews its identity itself.

ipam publishes its events (`platform:events:<tenant>`) to the core's event
bus (Valkey, TLS) as user `ipam`: the core's Valkey must accept that user
from this host. The gateway relays them to the browser; dns re-reads the
addresses they name.

Discovery scans and ping use raw ICMP sockets: the container keeps only
`NET_RAW`, and this host must route to the networks you scan.

warden (BMC credentials for power/KVM/sensors), inventory (host sync) and
the scheduler (scheduled scans) are not reached until their addresses are
added under `discovery.static` in `config.yaml` (see its header) and each
peer's policy allows `spiffe://<trust domain>/svc/ipam`. Until then
power/KVM/sensors answer `warden_unavailable` and `host_sync` /
`task_scheduler` stay disabled. Embedded KVM consoles also need the optional
console-origin input.
